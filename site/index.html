How it works

  1. Your Mac is the hub. The app runs a hub: a small SQLite database behind a tiny web server, one Python file. It holds your alerts; there's nothing else to install.
  2. Senders post to it. A Claude session, a cron job or a CI step runs the one-file needs-you command. If your Mac is asleep, the alert waits in a local outbox and goes out when it wakes.
  3. The pill shows it until it's handled. It floats over everything and never takes focus. The sender clears it, or you click Done. Nothing piles up.

Server hubs are optional, for redundancy: the same hub on an always-on Linux server, so alerts land while your Mac sleeps. Most people don't need one. Under the hood has the details and the measured numbers.

How agents use it

An agent posts only when it's blocked on you, with a link to where you act: the PR, the ticket, or the session's folder in your editor. Here, an agent on devbox asks before it runs a migration:

needs-you add --key "claude-code:devbox:acme-api" --priority urgent \
  --title "Claude needs permission: acme-api" \
  --link "VS Code=vscode://vscode-remote/ssh-remote+devbox/home/dev/acme-api"

Hooks for Claude Code and the other agents post these cards for you, and clear them once you answer. Agents posting on their own follow the agent guide: post when blocked, one key per thing, resolve it when it's handled.

What it looks like

Under the hood

A hub is a small SQLite database behind a tiny web server. It's one Python file that needs only the standard library. The Mac app runs one, so your Mac is the hub: nothing to install or keep running.

Senders are the one-file needs-you command. It tries each hub in turn. If none answers (your Mac is asleep, say), it keeps the alert in a local outbox, exits cleanly so the job carries on, and sends it later.

Server hubs are optional, for redundancy. Run the same hub on an always-on Linux server and it copies every write to your Mac's hub and back, so alerts land while the Mac sleeps. Most people don't need one.

The app checks every 30 seconds and keeps a live stream open, so new alerts show at once. With nothing new, a check is under 100 bytes and the stream sends a short ping every 15 seconds.

It cleans up after itself. Done and FYI cards expire after a day, closed items are deleted after 7 days, and a sender's outbox keeps at most 500 alerts for 7 days.

Install

Download for Mac

The latest release has NeedsYou-<version>.dmg (open it, drag the app to Applications) and the same app as a .zip. macOS 14 or later.

The app is ad-hoc signed, not notarized, so macOS blocks the first launch. On macOS 15 and later: double-click it, then System Settings → Privacy & Security → Open Anyway. On macOS 14: Right-click the app → Open → Open.

A faint pill appears at the top right, and your Mac is now the hub. To connect a sender (a server, a CI runner, or Claude Code on this Mac): right-click the pill → Settings… → Connect a machine → Create invite. Paste the Agent prompt into the machine's agent, or copy the Shell one-liner and run it there. Either way the machine gets the needs-you command and posts a test card. The one-liner looks like this (the Claude Code options are optional):

curl -fsSL <join_url>/install.sh | bash -s -- --yes --claude-hooks user --skill --alerts

Step by step: the Quickstart, the install guide for testers (first run, what to try, reporting problems), and Tailscale for servers and other machines. All guides.
