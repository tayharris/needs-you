# Test plan, 2026-10-08

Status: a checklist for the owner after the 2026-10-08 agent-team session (0.1.4 and what follows it). Everything below is merged and green on Linux and on the Mac's `/usr/bin/python3` 3.9 and Swift selftest, but these are the parts no test or agent could click or run against a real model. Tick each box, and write anything odd into a findings table like [doc-test-findings.md](doc-test-findings.md).

Throughout: **keep typing in another app.** The panel must never take focus (hard rule 2).

## 0. Setup

- [ ] The installed app is 0.1.4 or later (Settings → Updates, or `defaults read /Applications/NeedsYou.app/Contents/Info.plist CFBundleShortVersionString`).
- [ ] `needs-you update` on each sender machine, then `needs-you doctor`: every `WARN`/`FAIL` has one next step under it, and running it fixes the line.

## 1. Mac app

- [ ] **Arrival preview:** post an item with a link (`needs-you add --key test:preview --title "A long title that should wrap onto a second line in the preview" --link "Docs=https://example.com"`). The title wraps to two lines at most, the meta line is full width, and the link button sits on its own row below. Clicking the button opens the link and marks the card done; clicking elsewhere opens the panel at the card.
- [ ] **Hub not answering:** with a hub that never answers its health check (e.g. `launchctl setenv NEEDS_YOU_HUB_READY_TIMEOUT 5` and a stuck hub), the pill says **Hub not answering** and the panel shows **Restart hub**. Click it: the hub restarts and nothing takes focus. Unset the variable afterwards.
- [ ] **Hub switch keeps state:** snooze a card and put one under Later, then toggle Run hub on this Mac off and on (or switch hubs). The snooze and the Later hold survive; held cards don't rejoin the list.
- [ ] **Done vs seen:** open the panel and immediately click Done on a fresh card. It doesn't flash back.
- [ ] **Over 500 items** (optional, on a test hub): post 600 items; the panel's count reaches 600.

## 2. Agents against a real model

Each was run live against a fake local model server, not a real one. With your normal login on a real project:

- [ ] **Codex:** an approval prompt posts a card that clears on approve; `/clear` in one session doesn't clear another session's card.
- [ ] **Gemini CLI:** in a trusted folder, a waiting card posts and clears. In an untrusted folder nothing runs (expected; doctor says so).
- [ ] **opencode:** a waiting card in the TUI; `opencode run "…"` posts nothing.
- [ ] **Copilot CLI:** an edit or MCP-tool permission prompt (never captured live; expect "Copilot needs your approval"), and a shell-command prompt ("Copilot wants to run …").
- [ ] **Kimi Code:** permission card on a real approval; "waiting" card clears on the next prompt.
- [ ] **Grok Build:** a real **permission_prompt** (never seen live) posts "Grok needs permission"; the idle card arrives ~60 s after a turn and only once, even with the Claude Code hooks installed too.
- [ ] **Cursor** (replay only, needs your login): `--cursor-hooks user`, finish a turn: a "finished" card; your next prompt goes through (never blocked) and clears it.
- [ ] **Cline VS Code extension** (only the CLI was run): a finished task posts a card; a new task clears it.
- [ ] **Aider:** `--aider`, a reply leaves a "waiting" card; typing in Aider is unaffected; `/exit` then `needs-you flush` resolves it.

## 3. MCP server and agent instructions

- [ ] `curl -fsSL <invite link>/install.sh | bash -s -- --yes --mcp claude,codex` registers the server: `claude mcp list` shows `needs-you`, and a Claude session can call `needs_you_add` without shell access. `needs-you uninstall-hooks --mcp` removes exactly that.
- [ ] `--agent-instructions codex` appends a marked block to `~/.codex/AGENTS.md`; uninstall restores the file byte for byte.

## 4. Site

- [ ] https://needsyou.app on a phone and a desktop: the pill demo loops, stops when you click it, resumes after ~10 s; **Send a test alert**, the link button and Done all work; nothing overlaps at phone width.
- [ ] The guides index lists every supported agent under **Agents**.
